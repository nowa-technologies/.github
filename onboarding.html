SETUP · ~15 PHÚT (1 LẦN)

Setup máy local

Full: SETUP.md.

1. Accept invite + 2FA

  • Accept lời mời trong email vào org nowa-technologies
  • Bật 2FA: GitHub Settings → Password and authentication → Two-factor. Bắt buộc — không có sẽ bị kick.
  • Dùng app Authy / Google Authenticator / 1Password. Lưu recovery code offline.

2. Cài tools

# macOS
brew install git
brew install --cask visual-studio-code
brew install gh

# Windows: tải git-scm.com, code.visualstudio.com, cli.github.com
# Linux (Debian/Ubuntu): sudo apt install git gh ; sudo snap install code --classic

3. Config git

git config --global user.name "Your Full Name"
git config --global user.email "yourname@resonancetech.co"

4. Đăng nhập gh CLI

gh auth login
# → GitHub.com → SSH → Generate new SSH key → Login with web browser
gh auth status   # verify

5. Test access

git clone git@github.com:nowa-technologies/personal-workspace-<tên>.git
# clone được = OK ✓
⚠️ Troubleshooting nhanh

Permission denied (publickey) → gh auth refresh -s admin:public_key. Mất 2FA app → dùng recovery code, hoặc liên hệ Andy/Grace ngay.

§2 · PERMISSION — BDFL

Permission model

Mỗi repo có 1 task owner = người duy nhất merge được vào main. Bạn có thể tạo PR vào bất kỳ repo nào bạn có access, nhưng chỉ task owner mới merge.

Loại repoTask owner
Personal workspaceBạn
Personal project {tên}-{team}-{project}Bạn
Team reposTeam lead / PIC project
Shared repos (hub, agent-skills)@owners (Andy, Grace)

Trên personal workspace/project, bạn là task owner → tự merge mọi PR của mình (hoặc push thẳng main).

§3 · DAILY WORKFLOW

Standard PR flow

git checkout main && git pull
git checkout -b <team>/<tên>/<short-description>   # vd: mkt/amy/audience-fintech-lp
# ... làm việc ...
git add . && git commit -m "Add ..."

# → tạo Pull Request trên GitHub web → đợi task owner review + merge

Trong personal workspace

Free style hơn: push thẳng main được (bạn là task owner), commit không cần quá formal.

Branch

{team}/{tên}/{short-description} — kebab-case, max 5 từ, không underscore/camelCase. Optional type: {team}/{tên}/{feature|fix|content|docs|refactor|experiment}/{desc}.

Commit

{Verb imperative} {what} — vd "Add Q3 launch plan", "Fix typo in guideline". Không "updated stuff", "WIP".

File & folder

Folder + file .md: kebab-case. Special: README.md uppercase. Code: theo convention ngôn ngữ.

Repo mới vs folder?

Default: folder. Tạo repo mới khi: team khác own, campaign time-bounded năm sau, asset chung nhiều project dùng, internal tool standalone, personal project có deliverable.

§5 · FILE RULES

Owner cập nhật gì?

Mỗi workstream có owner theo .github/CODEOWNERS. Owner giữ workstream up-to-date: meeting notes (qua skill), partner artefacts/contracts (qua promote), workstream README.md. Trackers (series-log, active-tracker, decisions) tự sinh qua meeting-note reconcile — owner double-check trước khi commit.

⚠️ KHÔNG dùng promote cho

Drafts WIP (giữ local) · Sensitive (equity, shareholder, finance → ping Grace, route -private) · Media >50MB (Drive) · decisions.md (tự cập nhật qua reconcile).

REVIEWER

Review PRs

Khi member promote file, PR auto-tag CODEOWNERS theo path. Bạn nhận noti → review trong 24h business.

Checklist review

  • Right destination? Path đúng workstream + sub-folder (outbound/inbound/contracts)
  • Naming? YYYY-MM-DD_slug.ext, partner-original suffix nếu inbound
  • Sensitive routing? Equity/shareholder/finance → flag, nên ở repo -private
  • Bilingual (Permill)? EN-CN cả 2 section
  • Content reasonable? Quick scan (meeting note có decisions/actions; contract có chữ ký)

Decision: ✅ Approve / 💬 Comment / 🛑 Request changes → merge (squash + delete branch) khi clean.

FAQ

Câu hỏi thường gặp

Cần biết Git để dùng hub không?
Không. Skill /nowa-* xử lý hết Git. Chỉ cần git pull mỗi sáng.
Notion có bị thay bởi hub không?
Không. Notion vẫn canonical cho Tasks DB + Master Timeline. Hub mirror snapshot mỗi sáng.
Sáng phải đọc gì trong hub?
Không gì gấp. Chỉ git pull để agents có context mới.
Có vault cá nhân, cần promote hết lên hub không?
Không. Chỉ promote file đã final/approved (contract signed, meeting note processed, PRD merged).
Sensitive file routing như nào?
KHÔNG promote lên shared hub. Ping Grace → route nowa-os-knowledge-hub-private.
File >50MB upload đâu?
Không up hub. Drive → share link qua promote với 1-line note.
Skill lỗi — fallback?
GitHub Web UI: repo → "Add file" → upload tay (cần biết destination + naming). Hoặc ping Grace.
